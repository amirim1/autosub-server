# Refactoring

## Rules

- Сначала понять текущий поток данных и контракт.
- Не менять наблюдаемое поведение и публичные форматы.
- Делать маленькие последовательные шаги.
- После каждого шага запускать релевантные тесты.
- Переиспользовать существующие интерфейсы и не вводить универсальные абстракции без потребности.
- Не совмещать рефакторинг с функциональными изменениями без явного запроса.
- Не менять публичные `/json/`, `/sub/`, admin contracts или SQLite schema без отдельного плана миграции.
- После каждого шага проверять `python -m pytest -q` или минимальный релевантный набор и `python -m compileall -q *.py`.
